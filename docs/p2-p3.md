# P2 / P3 开发与验收

## 数据通路

TUI 启动 `dsh-v0.2.2-rc.5`（`9c2670d3bce5275e0d1610272958121af87787bb`）的官方 `sdk` profile。Runtime 使用独立的 `DSH_HOME`、`workspace-write` 和官方工具审批。SDK 的 stdout 传输 JSON-RPC 帧，stderr 写入 `runtime.log`。

- `dsh-protocol` 定义帧、方法和参数，并校验已审阅的 SDK 源码。JSON-RPC ID 支持上游使用的字符串和数字。
- `dsh-tui` 的 Runtime supervisor 通过有界 stdin、stdout 和 UI 队列处理请求和通知。最多同时跟踪 32 个客户端请求。超时后报告结果未知，供用户决定是否重试。退出时等待 SDK `shutdown`，到达截止时间则终止并回收子进程。
- `dsh-state` 按接收顺序保存通知和 Host 请求，包括重复项、未知事件和打包的文本增量。投影按会话序号去重，有限缓冲内重排，超出缓冲的迟到事件触发该会话重放。工具按轮次、步骤和调用 ID 关联，子会话按 SDK 的父子 ID 关联。注入上下文保留在事件记录中。
- TUI 从视口锚点向前或向后查找可见行。Markdown 和长工具输出分块排版并缓存，折叠覆盖按会话、工具组、调用或子会话标识保存。活动时约每 33 ms 合并绘制一次，空闲时等待输入或 SDK 事件。

## 功能验收

| 阶段 | 已验证 | 待验证或上游限制 |
| --- | --- | --- |
| P2 SDK 双向通信 | 初始化、请求关联、乱序响应、超时、异常退出、正常关闭。已知 ID 恢复和多轮 Prompt 经过真实 Runtime 测试 | Windows 进程生命周期缺少 PTY 验收 |
| P2 会话与事件 | 可新建、恢复、查询目录。测试覆盖原始事件、重复序号、重放、增量拼接、工具和子会话关系 | SDK 缺少会话列表和历史回填方法，当前会话列表与正文以 TUI 进程实际收到的信息为限 |
| P2 Host 交互 | 本地测试覆盖默认拒绝、允许一次、取消、结构化多选和自定义答案 | 真实 Runtime 审批和子会话交互仍需单独端到端验收 |
| P3 聊天与工具 | Unicode 多行编辑、选择、草稿恢复、三种显示模式、单项折叠、失败定位、视口随动和缩放 | Markdown 是终端子集，高亮覆盖围栏代码与行内代码，链接可读 |
| P3 路由 | `/route PROVIDER MODEL` 由 SDK 重初始化并校验，成功后恢复已知会话。PTY 已验证重连与上下文保留 | 固定版本缺少 Provider 或模型枚举接口。用户需输入官方配置中已有的路由，真实模型服务待验收 |

SDK 只发布落定的 `session.event`，其中可能包含打包的模型增量。受此限制，界面在收到落定事件后更新，逐 token 输出待上游开放接口。SDK 没有单任务取消方法。`Ctrl+C` 停止当前 Runtime 并重连，旧进程管理的任务都会受到影响。事件记录目前驻留在内存中，长时间运行时内存随事件总量增长。

## 原生 Runtime 验收

```sh
./scripts/build-runtime.sh
cargo build --locked -p dsh-tui
python3 scripts/test-runtime-chat.py
```

脚本在 Unix PTY 内运行真实 TUI 和固定版官方 Runtime，Provider 使用仅监听回环地址的 SSE 测试服务。首轮实际调用 `read` 读取临时目录中的合成文件，随后检查默认折叠、展开和显示模式。切换路由重新初始化并恢复原会话，第二轮确认 Provider 收到了首轮上下文。最后检查终端属性恢复与两个 SDK 进程均被回收。付费模型服务尚未验收。

## 性能基准

```sh
cargo test --locked --release -p dsh-tui benchmark_chat -- --ignored --nocapture
DSH_TEST_IDLE=1 python3 scripts/test-runtime-chat.py
```

峰值 RSS 可通过对 release 测试可执行文件运行 `/usr/bin/time -l`（macOS）或 `/usr/bin/time -v`（Linux）测量。测试文件路径可从 `cargo test --release -p dsh-tui --no-run` 的输出取得。

测量环境为 Apple M5、32 GiB、macOS 27.3 arm64、Rust 1.100.0、Node 26.13.1。基准采用 120×36 的 Ratatui TestBackend，输入为 100,000 个合成 SDK 事件，其中包括 10,000 条含打包增量的消息、1,000 次工具调用和约 1 MiB 的单次工具输出。随后向历史追加约 256 KiB 的 Markdown。绘制、滚动和编辑各采样 240 次。

| 指标 | 结果 |
| --- | ---: |
| 事件投影吞吐 | 69.75 ms，1,433,692 事件/秒 |
| 绘制 P50 / P95 / P99 | 0.060 / 0.071 / 0.197 ms |
| 滚动与绘制 P50 / P95 / P99 | 0.061 / 0.067 / 0.138 ms |
| 编辑与绘制 P50 / P95 / P99 | 0.060 / 0.065 / 0.068 ms |
| 测试进程峰值 RSS | 247.5 MiB |
| 132×32 PTY 空闲 5.02 秒 | TUI 0.20% CPU、SDK 0.00%、0 次终端输出 |

TestBackend 结果覆盖应用排版与绘制，实际终端的写入、图形绘制和从敲键到屏幕可见的延迟另需测量。下一轮优先跟进上游的实时增量、会话发现和单任务取消接口，并为现有事件记录建立内存预算。
