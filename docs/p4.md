# P4：长会话存储与离线回放

官方 Runtime 仍锁定在 `dsh-v0.2.2-rc.5`（`9c2670d3bce5275e0d1610272958121af87787bb`）。未修改 Agent Loop、上游源码、协议锁或自动同步工作流。

## 记录与内存预算

- 每次在线启动单独写一个 NDJSON 日志。已接收的 SDK 通知和 Host 请求先落盘再投影；未知类型和重复记录仍保留，去重只影响显示。日志保留解析后的内容，不保证与 wire 字节相同。轮次结束、退出时同步；重放忽略未写完的末行，拒绝损坏的完整行。没有到达 Host 的事件无法补回。
- 正文、工具参数、结果和错误存入临时磁盘文件；缓存最多 **8 MiB / 256 条**。可见内容按需读取，超预算单条不进入缓存。Markdown 布局最多 **4 MiB / 96 个分块**，代码围栏索引最多 **1 MiB / 16 个来源**。
- 这些是内容缓存预算，不是进程 RSS 上限。行与序号索引会随历史增长，处理单条大帧还有临时分配；日志不自动清理或轮转。正常退出删除临时正文文件，强制退出后可能残留。Unix 新建目录和文件权限为 `0700` / `0600`；日志未加密。
- `/history` 在后台枚举本 TUI 的会话；选择后从旧日志回填正文、工具结果和关联子会话，再走官方 `session/resume`。选中后的回填仍在前台扫描，历史很大时可能有可见停顿。日志远大于内存预算时也应预留磁盘空间。

## 回放既有 DSH 会话

先构建本仓库固定的官方 Runtime。选择一个已结束、不会继续写入的 `session.v4.jsonl.zstd` 文件；不要传会话目录或凭据文件。

```sh
cargo build --release --locked -p dsh-tui
replay_dir=$(mktemp -d)
runtime/upstream/node_modules/.bin/tsx scripts/export-dsh-session.mts \
  /path/to/session.v4.jsonl.zstd "$replay_dir/session.ndjson"
target/release/dsh-tui --replay-journal "$replay_dir/session.ndjson"
```

导出使用同一提交中的官方解压和会话格式恢复器，只支持当前压缩格式。它不连接 Agent、不改写源文件，也不需要凭据。输出路径必须不存在；导出失败时不要使用输出文件。离线 TUI 不执行回放中记录的工具或审批，只展示事件；Tab、Ctrl+L 与翻页键仍可用。导出的 NDJSON 仍含原始会话内容，使用完后可删除自己的导出文件。

## SDK 能力边界

依据固定提交的 [SDK 请求与通知类型](https://github.com/deepseek-ai/deepseek-harness/blob/9c2670d3bce5275e0d1610272958121af87787bb/packages/sdk/protocol/src/types.ts)、[Server 转发逻辑](https://github.com/deepseek-ai/deepseek-harness/blob/9c2670d3bce5275e0d1610272958121af87787bb/packages/sdk/server/src/server.ts)和[传输取消语义](https://github.com/deepseek-ai/deepseek-harness/blob/9c2670d3bce5275e0d1610272958121af87787bb/packages/sdk/protocol/src/transport.ts)：

| 能力 | 当前支持 |
| --- | --- |
| 逐 Token 输出 | SDK 转发已记录的 `session.event`，打包增量随消息到达；没有实时 Token 通道。 |
| 枚举与回填历史 | SDK 可恢复指定 ID，不提供枚举或历史事件流。Host 日志提供本机回填；既有官方会话通过独立离线入口打开。 |
| 单任务取消 | 传输的 `AbortSignal` 只移除请求等待者。TUI 保留进程级退出、回收及重连，不冒充单任务取消。 |

- 132×32 PTY，release TUI。每个样本 50 次按键、切换模式及 20 次翻页；操作期间 TUI CPU 为 2.06% / 1.77% / 2.80%，空闲观察 15 / 5 / 5 秒均为 0.00%、零终端输出。确认 Enter 不发送请求、无 Agent 子进程、退出恢复终端。Node 导出使用的官方恢复器会一次持有恢复后的会话，CPU 以单核 100% 计；它不是常驻 Runtime 的负载。
- 单独启动锁定的官方 SDK，不提交任何 Prompt：30.16 秒空闲，Rust TUI **0.10% CPU / 3.8 MiB RSS**，Node Runtime **0.00% CPU / 210.5 MiB RSS**，零终端输出；退出恢复终端并回收 Node。P3 的 5.02 秒短测为 0.20% / 0.00%，按键 P95/P99 为 45.96/46.80 ms；真实长历史下 P95 接近，最慢样本 P99 上升约 5.7 ms。不同内容与采样窗口不宜解释为严格 A/B。
- 同一 100,000 事件、120×36 `TestBackend` 基准：P3 写入投影 **71.43 ms**，峰值 RSS **247.5 MiB**；P4 磁盘记录 **197.11 ms**，峰值 **15.9 MiB**（约少 94%），原始日志 **17.8 MiB**。纯绘制 P95/P99 从 0.068/0.187 ms 变为 0.069/0.275 ms；翻页加绘制 P95/P99 从 0.067/0.137 ms 变为 0.068/0.125 ms。投影写入变慢，换来低常驻内存和持久回放。
